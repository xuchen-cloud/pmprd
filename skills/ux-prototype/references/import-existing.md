# 导入现有稿并保留业务设计

适用于“给这个 HTML 加交互说明”“接入协作格式”等任务。输入可以是普通 HTML、已知旧版评审导出或已有协作稿。导入的默认设计依据为 `existing`；除非用户要求视觉变化，否则不读 OpenTiny 资料、不换主题、不重排布局、不重写业务行为。

## 先识别输入与说明依据

用源码和浏览器确认业务页面、动态区域及现有协作外壳。记录可见页面与代表性交互的当前表现，再依据代码实际行为写说明。PRD 可作为比对材料；差异要明确说明，不能把需求直接当作已实现功能。说明写法和锚点规则见 [文件规范](file-format.md)。

- 普通 HTML：保留业务 DOM、样式、脚本与资源引用。
- 已有规范 `ux-review-document`：保留文档 ID、PRD、标注及全部历史，用 `annotate`／`apply` 追加；不重新 `init`。
- 已知旧版评审导出：读取 `window.__PRD_OFFLINE__` 中的业务原型及可读 PRD／历史；旧阅读器外壳不作为业务 HTML 保留。
- 旧 `ux-requirements` 协作层：迁移可读 PRD 与旧历史，移除已标记的协作块、旧元数据与对应文档入口。不要把普通业务弹窗、导航或包含“需求”字样的业务模块当成旧外壳删除。

未识别的外壳不要凭猜测手工删除。工具不保证迁移所有旧标注与扩展字段；保留源文件，并按报告列出未进入新稿的内容。可读旧历史归档到 `legacyHistory`，不重写成新修订事件；旧 HTML PRD 转为文本时不保留富文本格式、图片和链接目标。已有规范文档中的未分类旧标注需由人工确认，不能自动改成修改意见。

## 选择一次完成的命令

**只补充交互说明：**准备 notes 数组（`selector`、`body`，更新时加 `id`），直接运行：

```sh
node /abs/ux-prototype/scripts/uxdoc.mjs annotate /abs/original.html --annotations /abs/notes.json --output /abs/annotated.ux.html
```

`annotate` 自动导入普通／旧稿、建立锚点及说明 ID，并生成摘要；已有稿保留原身份。selector 必须静态唯一匹配，动态控件可选稳定容器并说明目标状态。完整 notes 示例、重复输入与更新语义见 [独立 CLI](cli.md#只补充或更新交互说明)。不要先把整页序列化重写后再注入。

**只接入协作格式或同时指定 PRD／标题：**使用 `init`，需要添加说明时再对其输出运行 `annotate`：

```sh
node /abs/ux-prototype/scripts/uxdoc.mjs init /abs/original.html --output /abs/imported.ux.html
```

`--prd /abs/prd.md`、`--title '页面名称'`、`--version 1` 和 `--design ID` 均可选；不指定时保留可读输入信息及默认 `existing` 设计。新增说明不要求先补一份臆造 PRD。已有协作稿需同时改 PRD、业务内容或处理修改意见时，按 [局部修改流程](cli.md#已有协作稿的局部修改) 使用 `apply`。

**每条导入路径都必须输出新文件。**保留源文件供核对，不能以清理旧外壳为由覆盖原稿。对于普通 HTML，允许的附加变化是协作元数据与稳定锚点；对于识别出的旧协作文件，还包括对应外壳的移除及内容迁移。

## 按导入范围验收

格式检查通过后，至少核对下面四类证据；已有协作稿后续简单小改仅复查受影响部分，不重新执行整份导入验收。

1. **DOM／源码对照：**确认业务结构、文案、CSS、脚本与资源未被重排或替换，变化限于锚点、元数据和已识别旧协作外壳；核对需要迁移的 PRD、历史与标注是否保留。
2. **代表性交互：**运行本次说明涉及的触发与反馈，包含必要的错误、空状态或取消路径；确认导入前后业务行为一致，标注在相应状态唯一定位。
3. **前后截图：**用相同视口与业务状态对照视觉，确认业务设计保持；旧协作入口的移除单独说明。无须为未影响的每个页面状态建立截图全集。
4. **控制台：**核对加载和上述交互中的新增错误及资源问题。受环境限制无法运行时明确列出未完成项，不把格式通过写成视觉或行为通过。

使用环境正常提供的浏览器运行方式，不把 `--no-sandbox` 当作默认启动参数。若页面依赖未内嵌资源，先报告现状；导入本身不授权下载或替换业务依赖。

交付新文件路径，并简短报告：**保留了什么、移除了什么、哪些内容未迁移或尚未核验**。读取命令返回的导入 `report` 辅助核对，不把它当作浏览器验收结果。若不存在某一类变化直接说明无；发现当前实现与 PRD 不符时一并指出，不擅自把导入扩大为功能重做。
