# 交付检查

围绕当前页面涉及的组件与流程选择检查项，检查深度与本次改动相匹配。

1. **文件与运行。** 运行 check_html.py，核对资源内嵌、id 唯一和 JavaScript 语法。在浏览器通过 file:// 打开成品，观察控制台及资源请求，确认本地模拟交互正常运行。
2. **流程与反馈。** 完成主要操作路径，检查加载、结果、错误重试、取消、关闭重开与草稿保留。每个可见操作提供对应反馈。
3. **输入与焦点。** 实际点击、Tab 进入、输入文字并提交空表单，检查正常、聚焦、错误、禁用和自动定位。Input 保持单层边框，outline 为0；按钮、链接与 Radio 分别保留键盘提示。核对 Enter、Esc、焦点返回及中文输入法。
4. **组件状态。** 核对组件变体、尺寸、字体、间距与解析后的 token。禁用按钮悬停仍保持禁用样式。Switch 普通/mini 尺寸及禁用色正确。标题使用600字重。Radio 默认白底空心，选中内点8px；鼠标选择显示单层卡片边框，键盘选择显示 Radio 焦点。
5. **布局与响应。** 按 Container 版型检查区域位置与独立滚动，按 Layout 栅格检查占栏数和768/992/1200/1920px断点。至少检查1440×900与768×900，需要移动端时增加390px。确认长字段、气泡及操作按钮完整可见，滚动到底部时内容可读。窄屏规则在构建后仍正确生效。
6. **导航与浮层。** 核对顶部、侧栏和品牌入口对应的内容、选中状态及面包屑。多层 dialog 按打开顺序检查 Tab、summary、焦点返回、提示所在层与滚动恢复。靠右气泡使用 align-end，并验证确认操作位于视口内。
7. **AI 与视觉。** AI 元素采用蓝紫渐变和双星标识，输入区以单层边框表达焦点，错误与禁用状态保持各自语义。截图检查页面及浮层的边框、圆角、字号、间距和层级，并核对深色系统偏好下的浅色主题表现。
8. **改动与交付。** 对照修改前的功能、文案、字段与已确认布局，确认本次改动符合需求。交付说明对应实际完成的检查，记录验证环境与范围。
9. **协作文件交付。** 本设计 skill 输出业务 HTML；如使用 ux-prototype，由其文件工具封装 PRD、两类标注与变更记录。在浏览器验证本次实现的业务流程和视觉状态，不向业务页面加入旧版需求与变更编辑器。

相关原始规范通过 component.py 按组件查阅；静态检查与浏览器交互检查配合使用。环境支持的检查结果直接记录，其他检查项注明验证条件。
